# Василий: сервер с бесплатным GroqCloud

GitHub Pages обслуживает PWA, но не выполняет серверный код и не может безопасно хранить API-ключ. Для настоящих ответов Василия нужен Node.js-сервер. Реальных ключей, платных ресурсов и демонстрационных ответов в приложении нет.

Сравнение бесплатных предложений на 18 октября 2026 года: [FREE_AI_OPTIONS.md](FREE_AI_OPTIONS.md). Основной адаптер использует GroqCloud и production-модель `openai/gpt-oss-120b` через Groq API. Выбранная модель получает только текст, без сканов и рукописи. Прежний OpenAI-адаптер сохранён для существующих подключений, автоматически он не включается.

## Действия владельца

1. Создайте аккаунт в [GroqCloud](https://console.groq.com/keys), проверьте доступность в своей стране и бесплатный тариф, создайте API-ключ. Не переходите на Developer/платный тариф и не добавляйте платёжные данные ради этого обновления.
2. На Node.js 22+ сервере задайте секрет `GROQ_API_KEY` и пароль входа `NOTEPAD_PASSWORD` длиной 16–256 символов. Это отдельный пароль вашего сервера, не пароль Groq/GitHub. Не присылайте ключ и пароль в чат. Используйте менеджер секретов хостинга или переменные окружения процесса, а не файлы репозитория.
3. Укажите `NOTEPAD_ORIGIN` — точный публичный адрес приложения на сервере, например `https://notes.example`, без пути и завершающего слеша. `PORT` по умолчанию 8080. Для разработки разрешён `http://127.0.0.1:8080` или localhost.
4. При необходимости задайте `NOTEPAD_DATA_DIR` — абсолютный путь к постоянному каталогу вне репозитория и публичного web-root. По умолчанию: `~/.my-notepad-server`. Дайте серверу право записи. Каталог содержит только счётчик квоты, не заметки и не ключи.
5. Запустите `node server/app.mjs`. Процесс слушает только loopback. Для публичного доступа настройте существующий HTTPS reverse proxy к этому порту. Сервер выдаёт PWA и API на одном сайте: сессия работает без сторонних cookie в Safari. Не открывайте loopback HTTP наружу напрямую.
6. Откройте HTTPS-адрес этого сервера → «Настройки» → «Василий» → «Подключение Василия» → «Проверить подключение». Адрес API подставляется автоматически, статический `config.js` менять не нужно. В появившейся форме введите пароль и нажмите «Войти». Затем откройте Василия через библиотеку и отправьте вопрос.

Развёртывание не переносит IndexedDB с GitHub Pages: хранилище привязано к origin. Перед переходом экспортируйте JSON-копию на старом сайте, импортируйте на новом и проверьте её. Не очищайте старые данные. Старый сайт продолжит работать независимо. API на постороннем сайте для приложения с GitHub Pages не рекомендуется: SameSite=Strict cookie намеренно не обходят ограничения Safari на сторонние сессии.

## Авторизация, квоты и ограничения

- Личный сервер использует один пароль владельца. Случайные 256-битные сессии хранятся в памяти. Cookie HttpOnly, SameSite=Strict, Secure при HTTPS, срок 8 часов. Выход отзывает сессию; перезапуск требует нового входа.
- Сравнение пароля использует scrypt и timingSafeEqual. API-ключ не передаётся клиенту. Неизвестные Origin для изменений отклоняются. GET статуса без Origin требует действующую сессию; без неё возвращается 401.
- До 10 попыток входа за 15 минут на сервер; 6 запросов модели в минуту и 20 за календарный день UTC на владельца, включая все сессии. Неуспешный запрос провайдеру тоже расходует локальную квоту. Повреждённый квотный файл закрывает доступ к модели, не сбрасывает лимит.
- Квота сохраняется атомарной заменой JSON-файла и последовательной очередью. Запускайте один процесс/экземпляр с постоянным диском. Для нескольких экземпляров нужен общий атомарный счётчик в БД. Не размещайте счётчик на эфемерном диске и не сбрасывайте при 429.
- До 6000 символов вложенного текста, 16000 суммарно для переписки и вложения, 1500 выходных токенов. Клиент удаляет из отправляемого контекста старые реплики, сохраняя текущий вопрос. Если вопрос с конспектом превышает предел, пользователь должен сократить его. Из заметки извлекаются доступный текст и данные диаграмм, без имитации OCR.
- При 429 вопрос сохраняется. Ошибки ключа/доступа требуют проверки серверной настройки. Ответы провайдера с ошибками не раскрываются клиенту. Автоматических платных fallback нет. У Groq отдельно действуют токенные лимиты организации: локальная квота не гарантирует отсутствие 429.
- Статический сервер выдаёт только PWA-ресурсы из списка service worker. `.env`, Git, серверные исходники, тесты и квоты недоступны. API и сессии не кэшируются service worker. Локальные `.env` и зависимости исключены в `.gitignore`.

## Проверка

Проверьте неправильный пароль (401), вход, статус (200), вопрос, выход и запрет API после выхода. GET `/api/assistant/status` сообщает провайдера и возможности без запроса к модели: он подтверждает конфигурацию и сессию. Реальные права ключа и доступ к Groq проверяются первым вопросом. Проверьте сохранность квоты после перезапуска и HTTPS на iPad.

```text
node --test tests/server.test.mjs tests/groq.test.mjs
node tests/run.mjs
```

Автотесты используют временные каталоги, тестовые пароли и подменённый транспорт провайдера. Браузерный тест проходит настоящий локальный HTTP-сервер, cookie-сессию, отправку смешанного конспекта, 429 и выход. Это не проверка настоящего ключа Groq, ответов реальной модели или физического iPad.
